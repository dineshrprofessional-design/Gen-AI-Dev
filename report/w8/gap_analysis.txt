1. THE GAP
------------------------------------------------------------------------------

   Gap = Outcome Pass Rate - Trajectory Pass Rate

   arm            outcome  trajectory       gap
   --------------------------------------------
   baseline        50.0%       80.0%    -30.0pp
   mitigated       50.0%       90.0%    -40.0pp

   The gap is NEGATIVE on both arms. That is the opposite of the textbook
   expectation and it is the headline finding of this analysis: in this
   system the trajectory is EASIER to pass than the answer, so a flawed path
   is not the main reason answers fail. Three cases per run walk a clean path
   and still produce an answer the scorer rejects.

3. THE FALSE POSITIVE — answer PASSES, trajectory FAILS
------------------------------------------------------------------------------

   Trace  : report/w7/smoke_agent.json, question w7-10
            (a real recorded run from the Week 7 Step 10 smoke tests)
   Query  : What is the rate limit on the /v1/embeddings endpoint?

   tool calls made     : 0
   LLM calls           : 1
   tokens              : 1,026
   answer              : INSUFFICIENT_CONTEXT
   refused             : True
   OUTCOME             : PASS   <- the scorer is satisfied
   TRAJECTORY          : FAIL   <- 0 steps below min_steps 1
   failure mode        : ['premature_refusal']

   Why this is a false positive, not a quibble
   --------------------------------------------

   The question asks for the rate limit on /v1/embeddings. No such endpoint
   exists in this corpus, so INSUFFICIENT_CONTEXT is the right answer and the
   Week 7 scorer passes it. But the agent called ZERO tools. It did not
   discover the absence; it asserted it.

   ANSWER_CONTRACT rule 2 reads: "If the tools do not contain the answer,
   reply INSUFFICIENT_CONTEXT." That is a claim about the tools, and it
   presupposes having consulted them. What actually happened is the model
   recognising from its own pretraining that an SDK like this has no
   /v1/embeddings route, and refusing on that basis.

   The harm is invisible here and severe elsewhere. The same behaviour on a
   question the corpus DOES answer produces a confident refusal of retrievable
   material. Outcome scoring cannot see the difference between these two
   cases, because on this question both produce the identical string. Only
   the trajectory separates them.

   This is failure mode 4 of the regression matrix: parametric guessing with
   verification bypassed. It is also why eval/week8_cases.yaml sets
   min_steps: 1 on w8-10 rather than 0 — a min_steps of 0 would have made
   mode 4 unmeasurable by construction, and the spec says so in its rationale.

4. HOW OFTEN
------------------------------------------------------------------------------

   18 agent runs of this question set were scored while building Week 8
   (10 baseline + 5 smoke + 3 targeted w7-10 samples). False positives found:
   1, the trace above. False negatives: 3 per full run, consistently.

   So the gap is not noise and it is not symmetric. Trajectory failures in
   this system predict outcome failures; the reverse does not hold. A single
   false positive was found only on the one question where the correct answer
   is a refusal - which is precisely the question where an unverified guess
   and a verified finding are indistinguishable from the outside.

5. WHAT THIS CHANGES
------------------------------------------------------------------------------

   Week 7 reported the agent at 50% outcome pass rate and concluded FIXED
   WORKFLOW. Trajectory evaluation does not overturn that - the agent's
   trajectory pass rate is higher than its outcome rate, so its planning was
   never the thing holding it back. If anything it sharpens the verdict: the
   agent's loop was doing its job and still bought nothing, because the
   failures were in wording and in one runaway, not in tool selection.
